# Инструкция агенту: рендер резюме на одну страницу

## Пререквизит

На входе должен быть готовый Markdown-текст резюме, адаптированный под конкретную вакансию.

## Цель

Получить PDF, который одновременно удовлетворяет двум условиям:

1. PDF состоит ровно из одной страницы.
2. После последнего видимого элемента резюме остаётся не более 3% свободной высоты рабочей области страницы. Поля страницы в расчёт не входят.

Иными словами, текст должен занимать не менее 97% рабочей высоты страницы. Нельзя объявлять рендер готовым, если выполнено только одно из двух условий.

## Неизменяемые ограничения

- Первый рендер каждой новой версии текста выполняй с темой `md-renderer/themes/default.json`.
- Не меняй формат и поля страницы, шрифт, размер шрифта, ширину контейнера или сам Markdown, если текущая ветка алгоритма требует только настройки вертикальных интервалов.
- Не редактируй исходный `default.json`. Для экспериментов создай рабочую тему, наследующую `default.json`, чтобы всегда можно было вернуться к исходным значениям.
- После сокращения или расширения текста сбрасывай все настройки интервалов и снова начинай с чистого `default.json`.
- После каждой правки обязательно заново рендери PDF и повторно измеряй число страниц и заполненность.
- Не оценивай заполненность визуально «на глаз».

Команда базового рендера:

```bash
python3 md-renderer/render_pdf.py path/to/resume.md \
  --config md-renderer/themes/default.json \
  --output path/to/resume.pdf
```

## Как проводить измерения

### Рабочая область

Рабочая высота страницы:

```text
Hwork = Hpage - Mtop - Mbottom
```

где:

- `Hpage` — полная высота страницы PDF;
- `Mtop` и `Mbottom` — верхнее и нижнее поля из активной темы.

Граница низа рабочей области:

```text
Ywork_bottom = Hpage - Mbottom
```

Свободная высота после текста:

```text
Hfree = max(0, Ywork_bottom - Ycontent_bottom)
```

где `Ycontent_bottom` — нижняя граница последнего видимого текстового или графического элемента на странице с учётом его реального line box. Пустые поля страницы не включай, но внутренний `padding` и вертикальные интервалы стилей считай частью рабочей области.

Процент свободного места:

```text
S = Hfree / Hwork * 100
```

Заполненность:

```text
F = 100 - S
```

Округляй значения только для отчёта. Решения принимай по неокруглённому значению.

### Подсчёт строк

Считай визуальные строки в готовом PDF после переноса текста, а не строки исходного Markdown:

- заголовок или пункт списка, занявший одну визуальную строку, считается одной строкой;
- каждая перенесённая часть абзаца или пункта считается отдельной строкой;
- пустые строки не считаются текстовыми строками;
- при многостраничном PDF строки вне первой страницы — все визуальные текстовые строки на страницах 2 и далее.

## Основной цикл

### 1. Выполни базовый рендер

Отрендери текущую версию резюме с `default.json`. Определи:

- число страниц `P`;
- число визуальных строк на каждой странице;
- `S` — процент свободного места после текста на первой странице;
- `F` — процент заполненности первой страницы.

Далее выбери ровно одну ветку алгоритма.

### 2. Если PDF состоит из одной страницы и `S <= 3%`

Рендер готов. Заверши работу и сообщи:

- путь к итоговому PDF;
- число страниц;
- число визуальных строк;
- заполненность `F`;
- использованную тему и все отличия рабочей темы от `default.json`.

### 3. Если PDF состоит более чем из одной страницы

Не пытайся уместить текст уменьшением шрифта, полей или интервалов.

1. Посчитай `Noverflow` — число визуальных строк на страницах 2 и далее.
2. Передай текст на сокращение и потребуй уменьшить результат как минимум на `Noverflow` визуальных строк относительно текущего рендера.
3. Попроси сохранить факты, релевантные вакансии ключевые слова, структуру разделов и Markdown-разметку.
4. Замени текст новой версией.
5. Сбрось рабочую тему и вернись к шагу 1 с чистым `default.json`.

Формулировка задания на сокращение:

```text
Сократи резюме минимум на {Noverflow} визуальных строк в рендере A4 с темой
default.json. Сейчас в PDF {P} страниц; за пределами первой страницы находятся
{Noverflow} строк. Сохрани проверяемые факты, релевантные вакансии ключевые слова,
структуру разделов и Markdown-разметку. Не меняй параметры рендера.
```

### 4. Если PDF состоит из одной страницы и `S > 15%`

Передай текст на содержательное расширение.

1. Посчитай текущее число визуальных строк `Ncurrent`.
2. Посчитай требуемое число строк для заполнения 95% страницы:

```text
Ntarget = ceil(Ncurrent * 95 / F)
Nadd = max(1, Ntarget - Ncurrent)
```

3. Попроси переписать резюме так, чтобы добавить примерно `Nadd` визуальных строк и довести ожидаемую заполненность до 95%.
4. Дополнять можно только релевантными вакансии фактами из исходных материалов. Запрещено выдумывать опыт, результаты, технологии или метрики.
5. Замени текст новой версией.
6. Сбрось рабочую тему и вернись к шагу 1 с чистым `default.json`.

Формулировка задания на расширение:

```text
Перепиши резюме под ту же вакансию и добавь примерно {Nadd} визуальных строк в
рендере A4 с темой default.json. Сейчас на странице {Ncurrent} строк и заполнено
{F}% рабочей высоты; целевая заполненность после переписывания — около 95%.
Добавляй только релевантные факты из исходных материалов, без выдуманных деталей.
Сохрани Markdown-разметку.
```

Заполнение до 95% — промежуточная цель. После получения нового текста основной цикл продолжается до достижения итогового порога 97%.

### 5. Если PDF состоит из одной страницы и `3% < S <= 15%`

Текст не переписывай. Увеличивай вертикальные интервалы в рабочей теме.

Выбери начальный параметр по текущему `S`:

| Свободное место `S` | Начальный параметр |
|---|---|
| `13% <= S <= 15%` | `li lineHeight` |
| `11% <= S < 13%` | `paragraph.lineHeight` |
| `9% <= S < 11%` | вертикальные `li margin` |
| `7% <= S < 9%` | `h2.marginTop` и `h2.marginBottom` |
| `5% <= S < 7%` | `h3.marginTop` и `h3.marginBottom` |
| `4% <= S < 5%` | `paragraph.marginTop` и `paragraph.marginBottom` |
| `3% < S < 4%` | `h1.marginTop` и `h1.marginBottom` |

Полный порядок параметров от рассчитанного начального параметра к следующему:

```text
li lineHeight
→ paragraph.lineHeight
→ li marginTop + marginBottom
→ h2 marginTop + marginBottom
→ h3 marginTop + marginBottom
→ paragraph marginTop + marginBottom
→ h1 marginTop + marginBottom
```

Начинай не с начала полного списка, а с параметра, соответствующего текущему диапазону `S`. Далее двигайся только вправо.

Шаг изменения:

- значения в `em`: `+0.05em`;
- значения в `px`: `+2px`;
- безразмерный `lineHeight`: `+0.01`.

Если парой меняются `marginTop` и `marginBottom`, увеличивай оба значения на один шаг за итерацию. Нулевое значение сохраняет исходную единицу соседнего параметра того же стиля; если единицу однозначно определить нельзя, используй `em`.

Для `h1`, `h2`, `h3` и абзацев используй реальные группы текущей темы: `h1`, `h2`, `h3` и `paragraph`. Группы `p` в теме нет.

Для элементов списка используй группу `li`, которая поддерживает `lineHeight`, `marginTop` и `marginBottom`:

```json
{
  "extends": "default.json",
  "styles": {
    "li": {
      "lineHeight": 1.11,
      "marginTop": "0",
      "marginBottom": "2px"
    }
  }
}
```

Для каждого выбранного параметра:

1. Увеличь параметр ровно на один шаг.
2. Отрендери PDF.
3. Повторно измерь `P`, `S` и `F`.
4. Если `P == 1` и `S <= 3%`, заверши работу.
5. Если `P == 1` и `S > 3%`, сохрани изменение и увеличь тот же параметр ещё на один шаг.
6. Если `P > 1`, откати только последний шаг до предыдущего успешного значения и снова отрендери PDF:
   - если после отката `P == 1` и `S <= 3%`, заверши работу;
   - иначе зафиксируй предыдущее значение и перейди к следующему параметру полного списка.

Уже принятые изменения предыдущих параметров при переходе к следующему параметру сохраняй.

Если список параметров исчерпан, а `S > 3%`, не объявляй рендер готовым. Передай текст на точечное расширение. Рассчитай число добавляемых строк по целевой заполненности 97%:

```text
Ntarget = ceil(Ncurrent * 97 / F)
Nadd = max(1, Ntarget - Ncurrent)
```

После расширения текста сбрось рабочую тему и начни цикл заново с `default.json`.

## Защита от зацикливания

- Сохраняй журнал каждой итерации: версия текста, тема, изменённый параметр, старое и новое значение, число страниц, число строк, `S` и `F`.
- Не повторяй комбинацию текста и настроек, которая уже проверялась.
- Любая новая версия текста начинает отдельную серию итераций с `default.json`.
- Если три последовательные переработки текста не меняют требуемое число строк в нужную сторону, остановись и сообщи о блокировке вместе с журналом измерений. Не ослабляй критерии готовности.

## Итоговая проверка

Перед завершением обязательно подтверди:

- [ ] PDF состоит ровно из одной страницы.
- [ ] Свободное место после текста рассчитано без полей страницы.
- [ ] `S <= 3%`, то есть `F >= 97%`.
- [ ] В PDF нет обрезанного, наложенного или вышедшего за рабочую область текста.
- [ ] Ссылки, маркеры списков и специальные символы отображаются корректно.
- [ ] Итоговые PDF и рабочая тема сохранены.
- [ ] Все отличия рабочей темы от `default.json` перечислены в отчёте.
